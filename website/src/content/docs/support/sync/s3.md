## Overview

ReadAny can use an S3-compatible bucket instead of WebDAV. Supported service types include AWS S3, Cloudflare R2, MinIO, Alibaba OSS, and Tencent COS, but any provider that implements the S3 API can work.

ReadAny is a client-side reader: you provide the bucket, credentials, and network access. The bucket is not a ReadAny service, and ReadAny does not manage your billing or retention.

## Setup

1. Open **Settings → Sync** and choose **S3**
2. Fill in **Service Endpoint**, **Region**, **Bucket**, and **Sync Folder**
3. Enter the **Access Key ID** and **Secret Access Key**
4. Set **Use path-style URL** if your provider requires it
5. Click **Test Connection**
6. Click **Save Configuration**, then **Sync Now**

### Field Reference

| Field | What to enter |
|---|---|
| **Service Endpoint** | The S3 API endpoint, including `https://`, for example `https://s3.example.com` |
| **Region** | The region required by your provider. Some S3-compatible services accept `auto`; AWS S3 requires a real region such as `us-east-1`. |
| **Bucket** | The bucket name. Create the bucket in the provider console first; ReadAny expects it to exist. |
| **Sync Folder** | The key prefix ReadAny owns, default `readany`. Nested prefixes such as `apps/readany` are supported. |
| **Access Key ID** | The access key for a scoped user or application key. |
| **Secret Access Key** | The matching secret. It is stored on this device by the app. |
| **Use path-style URL** | Forces `endpoint/bucket/key` addressing instead of `bucket.endpoint/key`. Enable it for MinIO, localhost, and raw IP endpoints; AWS S3 and most DNS-based providers can use virtual-hosted style. |

**Test Connection** checks that ReadAny can list the bucket under the configured prefix. It does not verify write, delete, or copy permission.

## Bucket Permissions

ReadAny uses these operations:

- List objects under the Sync Folder
- Get objects
- Put objects
- Delete objects
- Copy objects, used when moving a renamed book folder (copy + delete)

A scoped policy that allows `s3:ListBucket`, `s3:GetObject`, `s3:PutObject`, and `s3:DeleteObject` on the bucket and its objects is enough for normal sync. Create the bucket in the provider console before connecting ReadAny.

## Remote Layout

S3 has keys, not real directories. ReadAny writes the same logical layout as WebDAV under the **Sync Folder** prefix:

```text
<Sync Folder>/
├── sync/
│   ├── index.json
│   ├── books/<bookId>.json
│   ├── threads/<threadId>.json
│   ├── chat/<YYYY-MM-DD>.json
│   ├── profile/<table>.json
│   └── sessions/<YYYY-MM>.json
└── data/
    ├── books/
    │   └── <sanitized-title>-<bookId>/
    │       ├── <sanitized-title>.<book-ext>
    │       └── <sanitized-title>.<cover-ext>
    ├── file/                          # legacy layout only
    ├── cover/                         # legacy layout only
    └── file-manifest.json
```

The layout, book folder naming, rename migration, and legacy layout are the same as [WebDAV Sync](/ReadAny/support/sync/webdav/). With the default Sync Folder, logical paths such as `/readany/data/books/...` become keys such as `readany/data/books/...`. The Sync Folder prefix is lowercased before use: `Apps/ReadAny` is written as `apps/readany`.

## Sync Behavior

- Metadata and book files sync in separate phases.
- On S3, a normal sync does not bulk-download remote book files. Open a remote book to download it, or use **Settings → Sync → Advanced Options → Full Download**.
- Missing covers are downloaded during a normal sync even when book files are not.
- Failed book-file uploads retry on the next sync. Failed book-file downloads need the book opened again or a Full Download.
- LAN transfer is separate and can download missing books and covers over the local network.

See [WebDAV Sync](/ReadAny/support/sync/webdav/) for the full failure semantics and known limitations. S3 uploads also read the whole book into memory before sending, so S3 may be subject to the same large-file limitation. This has not been tested on S3.

## Security

- Use an HTTPS endpoint. Plain HTTP exposes credentials and book files.
- Create a scoped access key for ReadAny instead of using an account-wide administrator key.
- S3 stores objects as plain files from ReadAny's perspective. ReadAny does not add end-to-end encryption; the provider can read synced JSON and book files.
- Restrict the key to the bucket and prefix you use for ReadAny.

## Troubleshooting

| Symptom | Check |
|---|---|
| `SignatureDoesNotMatch` | Secret Access Key, Access Key ID, and Region |
| `NoSuchBucket` | Bucket name and Region; create the bucket in the provider console |
| `AccessDenied` | Bucket policy and key permissions for list/get/put/delete |
| Connection error or timeout | Endpoint URL, `https://`, DNS, firewall, and the provider's status |
| Bucket-style requests fail | Enable **Use path-style URL** (common for MinIO, localhost, and IP endpoints) |
| Objects land in an unexpected place | The **Sync Folder** prefix is part of every key; use a dedicated prefix |
